### 1. 初代 Switch 超频定档并打包

- 在清零时序、抬电压的条件下把 CPU / GPU / 内存各刷了一轮频率阶梯，最终定下一组长时间不崩的配置：CPU 约 2.2 GHz、GPU 998 MHz、内存 2133 MHz（实测 2131.5 MHz），配套自定义风扇曲线，满载核心温度稳定在 41–49°C。
- 把这一版稳过配置归档为「黄金包」：一个可直接替换的内核补丁、对应的 Aurora 预设 JSON、一份保守兜底预设（1866 MHz）和风扇曲线配置，附一份 README 记录实测数据、相对原厂的提升比例，以及撞墙边界（内存 ≥2200 MHz、更激进的 GPU 档位、更深的降压均实测崩溃）。
- 关键结论写进 README 而不是留在对话里：为什么必须用整包补丁而不是手改频率表、为什么不能把某档 GPU 降压模式与自定义电压表混用、纯电池与插电两种场景的频率该怎么拆。

## 问题与解决

- **切内核后机器失联**：给两台 VPS 换新版内核开启加速，其中一台重启后公网不通、内网也掉线，跳板机也连不上。判断是新内核对它的虚拟网卡或 initrd 不兼容，改内核这条路暂时搁置，准备在服务商面板里切回原内核再排查——这台机器的问题没解决，留到第二天。
- **靠猜不如读日志**：Antigravity 登录失败一开始看起来像账号问题，实际是服务环境缺代理变量；差异只在「交互式终端 vs systemd 服务」这一层。
- **手机手势全失效**：上滑回桌面、多任务、小窗、分屏同时失灵，第一反应是停用了某个系统组件。核对了桌面、SystemUI、悬浮窗、侧边栏相关进程全部在启用状态，真正原因是之前把三项动画缩放改成了非标准的 0.75——这套系统的手势回调节奏依赖原生 1.0 时间轴，加上桌面与 SystemUI 运行时长不一致导致状态脱节。恢复 1.0 并重启桌面后功能回来，用户确认已恢复。
- **调试工具本身挖坑**：排查时对无线调试执行了不带行数上限的日志抓取，直接挂住几分钟，只能中止改用定点查询。
