## 今日完成

- 给索尼 A7R2（ILCE-7RM2）搭好了相机应用管理环境。用的是官方逆向工具链 Sony-PMCA-RE，项目 2022 年后就没再更新，直接装在系统 Python 3.14 上会撞旧依赖，所以改用独立的 Python 3.12 虚拟环境 + 启动包装脚本；包管理器里没有现成打包，官方也只发了 Windows/macOS 版，没有更省事的路。
- 先确认机型可装性再动手：A7R2 属于 CXD90014 架构，应用安装、更新器、维修模式三档全支持；三代以后机型固件签名收紧，反而装不了第三方应用。
- 索尼已在 2025-08-31 关闭 PlayMemories 相机应用商店，官方渠道不再提供下载。绕开这一点，从社区存档取得 4 个官方应用、从作者仓库取得 2 个开源应用，逐个校验为结构完整的安装包并记录哈希。本机直连和代理都访问不到存档站，最终经境外中转取得文件。
- 解决相机 USB 访问权限：新增 udev 规则把该厂商设备放行给 plugdev 组，免去每次操作都要提权；当前用户已加入该组。
- 在相机上装完 7 个应用：焦点包围、包围曝光、平滑反射、触屏快门、遥控拍摄、文件系统服务，以及解锁类工具 OpenMemories: Tweak。每个都确认安装流程返回成功。
- 核实手机端遥控方案：Monitor+ 对 A7R2 的任何连接方式都不支持，有线兼容表最老只到三代；A7R2 本身没有蓝牙模块。可选项收敛到官方 Imaging Edge Mobile 配合相机端遥控应用走 WiFi。
- 核对三把检索服务密钥的可用性：一把额度耗尽，两把能正常返回结果。
- 把整套流程连同踩到的坑写成技能文档，留给以后复用。

## 问题与解决

- 批量连装会失败：一次性装 6 个应用只有 2 个成功，其余报 `Start not accepted (code=10)` 和 `Unknown rest message type: 0x504f`。改成「装一个、等 8–10 秒、先用 `info` 确认相机仍在线」后逐个重试，全部通过。安装完成时相机 USB 设备 ID 会切换，属正常现象。
- 某个文件服务应用连续三次报同一个 `Communication error 100`：错误完全一致说明是包本身与老系统不兼容，不是偶发。换成 2019 年的 0.2.0 版本后一次装成。
- 安装器打印 `Warning: Invalid apk file` 但流程照样走完：读源码后确认这条警告只来自安装前的「预检显示」，作用是打印包名和版本，解析失败被吞掉，不影响实际写入。又拿同一个解析器去跑已确认成功的包，发现它对所有包都报错，才排除了「包坏了」的误判。
- 依赖的 Python 版本错位：包管理器装的 USB 库只挂给系统默认解释器，隔离环境里看不到；补装进虚拟环境后设备识别正常。
- 首次识别报权限不足，设备属 root 且组不可写；用 udev 规则一次性解决，后续不再需要提权。
- 参数记错导致首轮安装全部失败：实际是 `-f` 而非 `-l`，修正后重跑。
