今天的主线是两件事：给本地编码 agent 换一个能用的模型后端，以及在没有付费搜索订阅的前提下，把可用的联网检索能力补起来。两件事都做到了可运行、可实测的程度。

## 今日完成

### 1. 安装并接管 omp（oh-my-pi）编码 agent

装上了 AUR 的预编译包 `oh-my-pi-bin` 18.20.2-1，由 pacman 管理，只有一个 glibc 依赖。选它的原因是 AUR 版本与上游 release 完全同版本、校验和固定，符合「优先预编译 `-bin`、交给包管理器」的原则。

安装后接了 Google AI Studio 的 Gemini 后端，配置写在模型定义文件里，8 个模型全部被正确识别：5 个 3.x flash 系列，加上 3 个 4 系列的 hydrogen / argon / carbon。

凭据没有以明文写进 YAML，而是用「运行时执行命令取值」的方式引用一个 600 权限的独立文件，这样配置文件本身可以安全备份。

### 2. 摸清 Gemini 免费档的真实配额

参数上 `gemini-4-hydrogen` 是 1M 输入 / 64K 输出、支持思考模式，看着很合适。实测下来免费档只有每天 20 次请求、每分钟 5 次；同代的 argon 和 carbon 限额直接是 0；3.1-pro 也是 0。真正能用的是 3.x flash 系列。

结论是 4 系列配上但标注「需付费」，日常选型走 `gemini-3.5-flash`。一个真实编码任务动辄几十次请求，每天 20 次撑不过一次调试。

### 3. 自建多源并行搜索 `msearch`

起因是想用 Grok 的服务端搜索做联网检索。调研后确认这条路走不通：xAI 的 OAuth 设备码登录要求 SuperGrok 或 X Premium+ 订阅，API key 又需要计费账号；而且 hosted `web_search` 是单独计费的，约每千次 5 美元，不在订阅范围内。

于是改做真正能用的东西——一个 Python 3 纯标准库的小工具，无虚拟环境依赖：

- 查询同时发给 Tavily、Exa、Firecrawl 三家，并行执行
- 用 RRF（倒数排名融合）合并，而不是直接比较各家 score——不同引擎的分数本来就不可比
- 按 URL 归一化去重，并标注 `matched_by`，同一个页面被几家同时命中一目了然，等于自带交叉验证
- 任一家失败不影响其余，抓取侧同样逐源降级
- 抓取不依赖任何搜索端点，单篇长文能一次取回四万多字符

同时把它注册成了 Hermes 技能，以后遇到内置搜索限流或需要第二意见时可以直接调用。

## 问题与解决

**paru 卡在 sudo 提示。** `paru -S` 停在密码输入不动，但 `sudo -n true` 能正常通过——说明免密本身没问题，是 paru 自己的提权方式失效。改用 `makepkg -si` 直接构建安装，一次通过。

**AUR 的 git 协议走代理报错。** `could not determine hash algorithm`，直连就正常。这和之前记录的「代理与 AUR 冲突」是同一个问题，改为直接下载 PKGBUILD 与源码包绕过。

**对配额的判断出过一次错。** 一开始把「每分钟 5 次」当成了「每天 5 次」，据此说模型基本不可用。被质疑后不再依赖二手推断，改为直接抓完整错误字段并做连打测试：`gemini-3.5-flash-lite` 一分钟连打 8 次全部 200 OK，直接否掉了错误结论；`gemini-4-hydrogen` 的 429 原文里写得很清楚，是 `GenerateRequestsPerDayPerProjectPerModel-FreeTier`、`limit: 20`。最后按模型分别列出 RPM 与 RPD，纠正了说法。

**tavily 在搜索链条中的定位。** 原本以为 `search` 强依赖 Grok 端点、整套工具都不可用；逐个文件核对后发现只有搜索这一环需要，抓取和站点结构映射完全独立，可以先把能用的部分配好跑起来，不必等订阅到位。
